# IAM 할당 매트릭스 — 설계

## 목표
누가 어떤 관리형 정책을 갖고 있는지, 어느 그룹에 속했는지를 표 하나로 보고, 칸을 눌러 바꾼다. 여러 칸을 바꾼 뒤 한 번에 미리보기 → 확인 → 적용한다.
- 정책 탭: 주체(사용자·그룹·역할) × 관리형 정책. 칸을 누르면 붙이기/떼기.
- 그룹 구성원 탭: 사용자 × 그룹. 칸을 누르면 넣기/빼기.
- 바꾼 칸은 장바구니에 쌓이고, 묶음 하나로 미리보고 적용하고 기록하고 되돌린다.

## 범위 밖
- 정책이 허용하는 내용을 칸으로 켜고 끄기(서비스 × 접근 수준 토글), 리소스를 끌어다 놓아 권한 주기. 다음 단계에서 따로 설계한다.
- 인라인 정책과 권한 경계 바꾸기. 표에는 표시만 한다.
- 열 구성 저장. 열 추가는 프로필을 바꾸거나 탭을 닫을 때까지만 남는다.
- 묶음에 붙이기·떼기·넣기·빼기 말고 다른 변경 담기.

## 화면
- IAM 메뉴에서 "정책" 아래에 "🧩 할당"을 둔다. 장바구니에 변경이 있으면 메뉴 옆에 개수를 보여준다. 화면 안에는 [정책] [그룹 구성원] 두 탭이 있다.
- 정책 탭
  - 행: 사용자·그룹·역할을 종류별 묶음으로 보여준다. 위쪽 칩([사용자] [그룹] [역할])으로 종류를 거르고, 툴바 필터는 행 이름에 적용한다(대소문자 무시, 부분 일치).
  - 열: 한 곳 이상에 직접 붙은 관리형 정책. 직접 붙은 주체가 많은 순서, 같으면 이름순이다. 권한 경계로만 쓰이는 정책은 열이 아니다. [열 추가]로 `iam_list_policies` 검색 결과에서 고른 정책을 열로 더한다.
  - 열 머리: 정책 이름, AWS 관리형/고객 관리형, 배지(관리자급, 권한 상승). 누르면 정책 상세로 간다.
  - 행 머리: 이름과 배지. 누르면 주체 상세로 간다. 행 끝에 "인라인 N"(`policyCount`에서 직접 붙은 관리형 정책 수를 뺀 값)과 "경계"를 표시하고, 누르면 주체 상세로 간다.
- 그룹 구성원 탭: 행은 사용자, 열은 모든 그룹(이름순)이다. 열 머리를 누르면 그룹 상세로 간다.
- 칸 상태
  - 정책 탭: ● 직접 붙음, ◐ 그룹으로 받음(그룹 이름을 함께 보여준다), ○ 없음. 직접 붙고 그룹으로도 받으면 ●에 ◐ 표시를 겹친다.
  - 그룹 구성원 탭: ● 속함, ○ 안 속함.
  - 대기 중인 변경: ＋ 붙이기·넣기, － 떼기·빼기.
- 칸 누르기
  - ○를 누르면 ＋, 다시 누르면 ○로 돌아간다(대기 취소). ●를 누르면 －, 다시 누르면 ●로 돌아간다.
  - ◐만 있는 칸은 바뀌지 않는다. 누르면 "<그룹> 그룹에서 받아요" 팝오버와 [그룹 행으로 가기]를 보여준다.
  - 잠긴 주체(서비스 연결 역할, Identity Center 역할: 지금의 `changeBlockReason` 규칙)는 행 전체 칸을 끄고 이유를 보여준다.
- 끌어서 칠하기
  - 바꿀 수 있는 칸을 누른 채 끌면, 처음 칸을 누른 결과 상태(붙음 또는 안 붙음)를 목표로 정한다. 끄는 동안 지나간 칸마다 그 목표가 되도록 대기 변경을 만들거나 지운다.
  - 실제 상태가 이미 목표와 같은 칸은 대기 변경을 지우고, 다른 칸에는 목표로 가는 대기 변경을 만든다. ◐만 있는 칸과 잠긴 행은 건너뛴다.
- 키보드: 표는 `role="grid"`다.
  - 화살표로 칸을 옮기고, Space로 토글한다. Shift+화살표로 범위를 넓히고, 범위에서 Space를 누르면 기준 칸을 토글한 결과를 목표로 범위 전체에 칠하기와 같은 규칙을 적용한다. Esc는 범위를 지운다.
  - 행 머리와 열 머리에서 Enter를 누르면 상세로 간다.
- "다른 주체와 같게"(행 메뉴)
  - 같은 탭의 다른 주체를 원본으로 고른다. 원본에 직접 붙은 정책(구성원 탭은 속한 그룹) 가운데 대상에 없는 것은 붙이기·넣기로 담는다.
  - 대상에만 있는 것은 목록으로 보여주고, 체크한 것만 떼기·빼기로 담는다. 처음에는 모두 체크하지 않은 상태다.
  - 그룹으로 받은 것은 비교하지 않는다. 대상이 잠긴 주체면 메뉴를 끈다.
- 행은 보이는 부분만 그린다(고정 행 높이, 외부 라이브러리 없이). 머리 행과 머리 열은 고정한다.

## 장바구니
- IAM 탭이 가지고 있어서, IAM 안의 다른 화면을 보고 돌아와도 남는다. 프로필을 바꾸거나 IAM 탭을 닫으면 비운다.
- 담긴 순서를 지킨다. 같은 (대상, 정책)이나 (사용자, 그룹)에는 변경이 하나만 있다. 반대 칸을 누르면 담긴 변경을 지운다.
- 50개까지 담는다. 51번째부터는 "한 번에 50개까지 담을 수 있어요"를 보여주고 담지 않는다.
- 개요를 다시 불러오면 장바구니를 정리한다.
  - 이미 목표 상태가 된 변경은 "이미 붙어 있어서 뺐어요" 같은 알림과 함께 뺀다.
  - 대상이나 정책·그룹이 없어진 변경은 "<이름>이 없어서 뺐어요"와 함께 뺀다.
- 아래쪽 막대에 "변경 N개 · <첫 변경 요약> 외 N-1개"와 [모두 취소] [미리보기]를 둔다. 펼치면 변경 목록이 나오고, 항목마다 ×로 뺄 수 있다.
- 다른 화면의 하나짜리 변경(붙이기 버튼, 빠른 조치 등)은 지금처럼 바로 미리보기로 간다. 장바구니와 섞지 않는다.

## 묶음 미리보기와 적용
- 정렬: 붙이기와 넣기를 앞에, 떼기와 빼기를 뒤에 둔다. 각 무리 안에서는 담긴 순서를 지킨다. 이 순서가 화면에 보이는 순서이자 적용 순서다. 앱이 자기 권한을 줄이는 묶음이라도, 중간에 남은 변경을 적용할 권한을 잃지 않게 하려는 것이다.
- 계산(순수 함수)
  1. 정렬한 변경 c1..cn을 가상 스냅숏 s0에서 차례로 반영해 s1..sn을 만든다.
  2. 변경 ci의 요약, 호출, 막힘, 주의는 s(i-1) 기준으로 계산한다. 지금의 변경 하나짜리 규칙과 같다.
  3. 영향과 묶음 경고(앱이 쓰는 자격 증명의 권한 축소·조건부 전환, 새 관리자급·권한 상승, 읽지 못한 정책)는 s0와 sn을 한 번 비교해 계산한다. 영향받는 주체는 각 변경에서 영향받는 주체를 합친 것이다.
  4. 되돌릴 수 있음 = 막힘 없음, 모든 변경에 역변경 있음, sn에서 앱이 역변경 호출 권한을 잃지 않음.
- 막힘
  - 변경 하나라도 막히면 묶음 전체를 적용할 수 없다.
  - 묶음에 붙이기·떼기·넣기·빼기 말고 다른 변경이 있으면 막힌다: "묶음에는 붙이기·떼기·넣기·빼기만 담을 수 있어요".
  - 같은 대상에 대한 변경이 겹치면 막힌다: "같은 대상을 바꾸는 변경이 겹쳐요".
  - 50개를 넘으면 막힌다: "한 번에 50개까지 적용할 수 있어요".
- 확인 문구: 확인 경고(변경별이든 묶음 전체든)가 하나라도 있으면 입력해야 한다.
  - 묶음의 모든 변경이 대상 하나에 몰려 있으면 그 대상의 이름이다. 대상은 붙이기·떼기면 주체, 넣기·빼기면 사용자다.
  - 대상이 여럿이면 "변경 N개 적용"(N은 묶음의 변경 수)이다.
  - 확인 이유와 대상 목록은 그대로 보여준다.
- 계획 비교: 지금의 계획 저장소를 쓴다. 키는 (프로필, 정렬한 변경 목록의 JSON)이다.
  - 기억하는 것: 계정, 변경마다의 호출(순서 포함), 막힘·확인 문구, 변경마다의 요약, 되돌릴 수 있음, 확인 문구.
  - 적용 때 다시 계산해 하나라도 다르면 묶음 전체를 거부한다: "미리보기 뒤에 IAM이 바뀌었어요. 미리보기를 다시 받아 주세요".
  - 미리보기 하나로는 한 번만 적용한다. 10분이 지난 미리보기는 쓰지 않는다.
- 적용
  - 정렬한 순서대로 변경마다 `write.rs`의 쓰기를 실행한다.
  - 변경마다 기록을 한 줄 남긴다. 같은 묶음은 같은 `batchId`를 쓴다.
  - 실패하면 그 변경을 실패로 기록(그때까지 성공한 호출 포함)하고 멈춘다. 뒤의 변경은 실행하지 않는다.
  - 이미 적용된 변경은 그대로 둔다(자동 되돌리기 없음).
- 결과 화면
  - 모두 성공하면 지금처럼 알림을 보이고, 3초 뒤 IAM을 다시 불러오며, 장바구니를 비운다.
  - 중간에 실패하면 "N개 중 k개를 적용하고 k+1번째에서 멈췄어요: <요약>: <이유>"를 보인다. k>0이면 [적용된 k개 되돌리기]를 보인다. 장바구니에는 적용하지 못한 변경만 남긴다.
  - 적용 전에 거부되면(계획이 달라짐, 확인 문구 불일치 등) 아무것도 바뀌지 않는다. 지금처럼 "미리보기 다시 받기"로 이끈다.
- 묶음 되돌리기
  - `iam_undo_batch(batchId)`는 그 묶음에서 성공했고 아직 되돌리지 않은 기록의 역변경을, 적용 순서의 반대로 돌려준다(되돌릴 기록 id와 짝지어).
  - 화면은 그 묶음을 다시 미리보기에 올리고, 적용하면 원래 기록마다 "되돌림"을 표시한다.
  - 역변경은 붙이기↔떼기, 넣기↔빼기다. 반대 순서로 뒤집으면 붙이기·넣기가 저절로 앞에 오므로 정렬 규칙과 어긋나지 않는다.
- 변경 기록 화면: 같은 `batchId`의 기록을 "묶음 · 변경 N개 · <시각>" 머리 아래 묶어 보여주고, [묶음 되돌리기]를 둔다. 다른 계정에서 한 묶음이거나 되돌릴 것이 없으면 이유와 함께 끈다. 하나짜리 [되돌리기]는 그대로 둔다.
- IAM 쓰기 API 호출은 계속 `src-tauri/src/iam/write.rs`에만 둔다.

## 계약 (추가만, serde camelCase)
```ts
interface PrincipalSummary {
  // …지금 필드
  attached?: string[];   // 직접 붙은 관리형 정책 ARN. 비면 보내지 않음(없으면 [])
  groups?: string[];     // 사용자만: 속한 그룹 이름. 비면 보내지 않음(없으면 [])
  boundary?: string;     // 권한 경계 정책 ARN. 없으면 보내지 않음
}

iam_preview_batch(profile: string, changes: IamChange[]): BatchPreview
iam_apply_batch(profile: string, changes: IamChange[], confirmText: string | null, undoOf: string[] | null): BatchResult
  // undoOf: 되돌리기 묶음이면 changes와 같은 길이, i번째 변경이 되돌리는 기록 id. 정렬할 때 변경과 짝을 지어 함께 옮긴다
iam_undo_batch(batchId: string): { changes: IamChange[]; undoOf: string[] }

interface BatchPreview {
  changes: {                         // 적용 순서대로
    change: IamChange; summary: string;
    calls: { api: string; params: Record<string, string> }[];
    warnings: { level: "block" | "confirm" | "warn"; message: string }[];   // 이 변경에서 나온 막힘·확인·주의
  }[];
  impacts: Impact[]; impactsOmitted?: number;   // 묶음 전체의 증감(지금 ChangePreview와 같은 모양과 한도)
  warnings: { level: "block" | "confirm" | "warn"; message: string }[];     // 묶음 전체(영향 비교와 묶음 규칙에서 나온 것)
  confirmText: string | null;
  reversible: boolean;
}
interface BatchResult {              // 적용 전에 거부되면 AppError
  batchId: string;
  logIds: string[];                  // 적용한 변경의 기록 id(적용 순서)
  failed: { index: number; summary: string; message: string } | null;   // index: 0부터, 적용 순서 기준
  notes?: string[];                  // ApplyResult.notes와 같다
}
interface ChangeLogEntry {
  // …지금 필드
  batchId?: string;                  // 묶음으로 적용한 변경. 없으면 보내지 않음
}
```

## 구조
- Rust
  - `iam/view.rs`·`iam/summary.rs`: 주체 요약에 `attached`·`groups`·`boundary`.
  - `iam/change/batch.rs`: 정렬, 순차 반영, 합친 영향과 경고, 확인 문구, 되돌릴 수 있음. 순수 함수.
  - `iam/commit.rs`·`iam/commit/plan.rs`: 묶음 계획 기억과 비교, 묶음 적용(멈춤 규칙, 기록).
  - `iam/log.rs`: `batchId`, 묶음 되돌리기 목록.
  - `iam_commands.rs`: 새 명령 세 개.
- 프론트 `src/iam/`
  - `assignments.ts`: 순수 로직. 개요에서 표 만들기, 칸 상태, 칠하기 목표, "다른 주체와 같게" 차이, 장바구니 정리.
  - `useAssignmentDraft.ts`: 장바구니 상태.
  - `Assignments.tsx`: 화면과 탭.
  - `AssignmentGrid.tsx`: 표(보이는 행만 그리기, 칠하기, 키보드).
  - `BatchPreviewDialog.tsx`: 지금 미리보기의 영향 목록과 확인 입력을 다시 쓴다.
  - `useIamBatch.ts`: 묶음 미리보기·적용·되돌리기 흐름.
  - `ChangeLog.tsx`: 묶음 표시.
  - `IamNav.tsx`·`route.ts`: `assignments` 화면과 장바구니 개수.

## 테스트
- Rust(순수 함수 중심)
  - 정렬 규칙.
  - 순차 반영: 같은 주체에 붙이기 뒤 떼기가 오면 떼기는 붙이기가 반영된 상태에서 계산한다.
  - 합친 영향: 정책을 바꿔 붙이면 실제 차이만 남는다.
  - 확인 문구: 대상이 하나일 때와 여럿일 때.
  - 묶음 막힘: 다른 변경 종류, 겹침, 50개 초과.
  - 계획 비교: 미리보기 뒤 IAM이 바뀌면 거부, 두 번째 적용 거부, 미리보기 없는 적용 거부.
  - 중간 실패: 멈춤, 기록, 뒤 변경 미실행. 쓰기 함수는 가짜를 넣는다.
  - 묶음 되돌리기: 순서와 짝, 이미 되돌린 기록 빼기.
