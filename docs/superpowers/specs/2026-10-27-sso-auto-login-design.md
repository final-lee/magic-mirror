# SSO 자동 로그인 — 설계

## 목표
SSO 프로필의 세션이 만료돼 명령이 실패하면, 사용자가 [로그인]을 누르지 않아도 앱이 `aws sso login`을 시작한다. 로그인이 끝나면 화면을 다시 불러온다. 프로필을 고를 때, 앱을 시작해 마지막 프로필을 복원할 때, 쓰는 도중 만료될 때 모두 같다. 브라우저 승인은 사용자가 한다(AWS가 요구한다).

## 범위 밖
- 만료 전에 미리 로그인하기(토큰 캐시 파일을 직접 읽어야 해서 뺀다).
- S3 전송 이벤트의 오류 문자열에서 만료를 감지하기. 다음 목록 호출에서 감지된다.

## SSO 프로필 판별 (`~/.aws/config`)
- `ProfileInfo`에 `ssoLogin: string | null`과 `ssoKey: string | null`을 더한다.
- 프로필 섹션(`[default]`, `[profile X]`)에 `sso_session`이나 `sso_start_url`이 있으면 SSO 프로필이다.
  - `ssoLogin`은 자기 이름이다.
  - `ssoKey`는 `session:<sso_session>`이고, `sso_session`이 없으면 `url:<sso_start_url>`이다.
- 둘 다 없고 `source_profile`이 있으면 체인을 따라가 처음 나오는 SSO 프로필을 쓴다. `ssoLogin`은 그 프로필 이름이고 `ssoKey`는 그 프로필의 키다. 최대 5단계까지 따라가고, 순환이면 멈춘다.
- 그 밖의 프로필은 둘 다 null이다. 이런 프로필은 자동 로그인하지 않고, 지금처럼 오류만 보여준다.
- `[sso-session X]` 섹션은 프로필이 아니다.

## 감지
- 프론트엔드의 모든 Tauri 명령 호출은 `src/api/invoke.ts`의 래퍼를 지난다. 이 래퍼를 `api/client.ts`, `explorer/api.ts`, `iam/api.ts`, `vpcmap/api.ts`가 쓴다.
- 래퍼는 실패가 `{kind:"ssoExpired"}`이고 인자에 `profile`이 있을 때 로그인 관리자에게 그 프로필을 알린다.
- 원래 오류는 그대로 다시 던진다. 호출한 쪽의 동작은 바뀌지 않는다.
- 백엔드가 `ssoExpired`로 분류하는 것은 SSO 토큰이 없거나 만료됐거나 포털이 거절한(401) 경우다. 다시 로그인해도 풀리지 않는 실패를 만료로 보면 자동 로그인이 브라우저를 헛되이 열기 때문에, 다음은 만료로 보지 않는다.
  - 자격 증명 단계의 거부, 곧 역할 맡기(`sts:AssumeRole`) 거부와 포털의 403(`sso:GetRoleCredentials`)은 만료가 아니라 `accessDenied`다. 맡으려는 역할의 ARN에 `AWSReservedSSO_`가 들어 있거나 응답 헤더에 `AWS SSO`가 있어도 같다.
  - 자격 증명을 만들 수 없는 프로필은 만료가 아니다. 토큰 전용 `sso_session` 프로필(`sso_account_id`와 `sso_role_name`이 없다)과 설정이 잘못된 프로필이 그렇다. SDK가 "no credentials found in chain"이나 "not properly configured"를 내고, 분류는 이 둘을 SSO·토큰 검사보다 먼저 보고 `other`로 SDK 메시지를 그대로 보여준다.

## 로그인 관리자 (`useSsoLogin`, App에 하나)
상태는 `ssoKey`마다 `idle | running | failed(이유) | cancelled` 중 하나다.
- `idle`에서 만료를 알리면 `running`이 되고 `sso_login(ssoLogin)`을 부른다. 같은 키가 이미 `running`이면 무시한다. 로그인은 하나만 돈다.
- 성공하면 `idle`로 돌아간다. 같은 `ssoKey`를 쓰는 모든 프로필의 쿼리(`account`, `resources`, `s3`, `diff`, `vpc-topology`, `iam`)를 무효화해 다시 불러온다. 무효화하기 전에 그 쿼리 가운데 켜져 있고 조회 중인 것은 먼저 취소해서, 로그인 뒤에 새로 시작하게 한다.
- 성공한 뒤에도 자동으로 다시 열지 않는 경우가 둘 있다(자동 재시도 막기, 사용자 결정).
  - 그 성공보다 먼저 시작한 호출의 만료 보고는 낡은 것이라 무시한다. 래퍼는 호출 시작 시각을 함께 알린다.
  - 성공 뒤에 시작한 호출이 5분 안에 또 만료를 알리면 새로 열지 않는다. 그 키를 실패로 두고, 배너에 "<프로필>: 로그인했는데도 자격 증명을 받지 못했어요. 프로필 설정을 확인해 주세요"를 보여준다.
- 자동 로그인은 지금 고른 프로필의 세션만 연다. 방금 떠난 프로필에서 늦게 온 보고는 무시한다. 직접 누른 로그인은 언제나 연다.
- 실패하면 `failed(이유)`가 되고, 사용자가 [취소]를 누르면 `cancelled`가 된다. 이 두 상태에서는 만료를 알려도 자동으로 다시 시작하지 않는다. 브라우저가 반복해서 뜨지 않게 하려는 것이다.
- 다음 경우에는 그 키가 다시 시작한다.
  - 사용자가 그 프로필을 다시 고른다. 명시적인 요청으로 본다. 다시 고르기는 실패·취소 기록만 지우고 성공 뒤 5분 창은 그대로 둔다. 그래서 로그인에 성공한 지 5분 안에 다시 골라서 또 만료로 실패하면 새 로그인을 열지 않고 "로그인했는데도 자격 증명을 받지 못했어요" 줄이 다시 뜬다. 그 창은 자동 재시도 막기(사용자 결정)의 일부라서 다시 고르기로 풀지 않는다.
  - 사용자가 [다시 로그인]이나 오류 화면의 [로그인]을 누른다. 직접 누른 시작은 5분 창 안에서도 로그인한다.
- 서로 다른 SSO 세션은 동시에 로그인할 수 있다.

## 화면
- 업데이트 배너 아래에 `SsoBanner`를 둔다. `running`이나 `failed`인 키마다 한 줄이다.
  - running: "<프로필>: SSO 로그인 중이에요. 브라우저에서 승인해 주세요" [취소]
  - failed: "<프로필>: SSO 로그인에 실패했어요: <이유>" [다시 로그인] [닫기]. [닫기]를 누르면 상태가 `cancelled`가 된다.
  - cancelled: 배너가 없다.
- 기존 `ErrorState`(ssoExpired)의 [로그인] 버튼은 관리자를 거쳐 시작하거나 진행 중인 로그인에 합류한다. `running`이면 "브라우저에서 로그인을 완료하세요…"로 꺼진다.
- 켜진 쿼리의 오류 화면은 로그인이 성공해도 따로 다시 불러오지 않는다. 로그인 관리자의 무효화가 그 쿼리를 다시 부른다. 상자마다 앱 전체 새로 고침(`onRetry`)을 부르면 같은 로그인 하나에 IAM 개요를 강제로 다시 읽는 일 같은 비싼 작업이 상자 수만큼 겹치기 때문이다.
- 누를 때만 도는 쿼리(`enabled: false`: 안 쓰는 권한, 시뮬레이터)는 무효화로 다시 불리지 않는다. 그 상자만 `onLoggedIn`으로 자기 쿼리의 `refetch`를 받는다. 상자는 자기가 뜬 뒤 그 세션의 로그인이 성공하면(자동이든 버튼이든 같다) 한 번 부르고, 같은 성공으로는 다시 부르지 않는다. `onLoggedIn`이 없는 상자는 아무것도 더 하지 않는다.

## 백엔드
- `sso_login(profile)`:
  - 로그인 대상의 키는 그 프로필의 `ssoKey`이고, 없으면 `profile:<이름>`이다.
  - 같은 키로 이미 진행 중이면 새로 띄우지 않고 그 결과를 함께 기다린다.
  - 성공하면 같은 `ssoKey`를 쓰는 모든 프로필의 `SdkConfig` 캐시를 비운다.
  - aws CLI 후보 경로와 "aws CLI를 찾을 수 없어요" 오류는 지금 그대로다.
- `sso_login_cancel(profile)`(새 명령):
  - `profile`은 프론트엔드가 `sso_login`에 넘긴 프로필, 곧 `aws sso login`에 넘어간 대상이다. 도는 로그인이 그 대상을 기억하고, 취소는 그 대상으로 도는 로그인의 프로세스를 끝낸다. 취소하는 순간의 `~/.aws/config`로 키를 다시 계산하지 않는다. 로그인이 도는 동안 config를 고쳐도 취소가 빗나가지 않게 하려는 것이다.
  - 진행 중이 아니면 아무것도 하지 않는다.
  - 기다리던 `sso_login`은 `other("로그인을 취소했어요")`로 끝난다.

## 계약 (추가만)
- `ProfileInfo { name, region, ssoLogin: string | null, ssoKey: string | null }`
- `sso_login(profile) -> ()`: 이미 있는 명령이다. 이름과 인자는 그대로이고, 위 동작을 더한다.
- `sso_login_cancel(profile) -> ()`: 새 명령.

## 테스트
- Rust:
  - 설정 파싱: `sso_session`, `sso_start_url`, `source_profile` 2단계, 순환, SSO가 아닌 프로필, `[sso-session]` 섹션.
  - 단일 실행: 가짜 실행기로 같은 키를 두 번 부르면 실행은 한 번이고 결과는 같다.
  - 취소: 대기 중에 취소하면 "로그인을 취소했어요"가 나온다. 취소는 도는 로그인이 기억한 대상으로 찾고, 그동안 config를 고쳐 키가 달라져도 빗나가지 않는다.
  - 분류: 실제 SDK chain으로, 진짜 만료는 만료로, 토큰 전용·설정 오류·자격 증명 없는 프로필은 만료가 아니게 본다.
  - 성공하면 같은 키를 쓰는 프로필의 캐시를 비운다.
- 프론트엔드:
  - 래퍼는 `ssoExpired`에 `profile`이 있을 때만 알린다.
  - 관리자:
    - 첫 알림에 시작한다.
    - 동시에 여러 번 알려도 한 번만 시작한다.
    - 실패한 뒤에는 자동으로 다시 시작하지 않는다.
    - 프로필을 다시 고르면 다시 시작한다.
    - 성공하면 쿼리를 무효화한다.
    - 취소할 수 있다.
  - 배너가 상태에 맞게 표시된다.
  - `ErrorState` 버튼이 관리자를 거친다.
  - `ErrorState`는 같은 성공으로 `onLoggedIn`을 한 번만 부르고(오류 종류가 바뀌었다 돌아와도), `onLoggedIn`이 없으면 아무것도 더 하지 않는다. 켜진 쿼리는 무효화로만 다시 불린다.
- 수동(`docs/manual-test-checklist.md`):
  - `aws sso logout` 뒤 앱을 시작하면 브라우저가 자동으로 열리고, 승인하면 목록이 저절로 불러와진다.
  - 프로필을 바꿔도 같다.
  - [취소]를 누르면 다시 열리지 않는다.
  - 같은 SSO 세션을 쓰는 두 프로필에서 로그인은 한 번이다.
