# 수동 테스트 체크리스트

실제 SSO 프로필로 `npm run tauri dev` 실행 후 확인한다.

## 기본
- [ ] 첫 실행 시 16개 서비스가 모두 사이드바에 보인다
- [ ] 프로필 드롭다운에 `~/.aws/config`의 프로필이 모두 보이고, 바꾸면 그 프로필의 기본 리전으로 바뀐다
- [ ] 앱을 재시작하면 마지막 프로필/리전/활성 서비스/즐겨찾기가 복원된다
- [ ] 상태바에 프로필 · 계정 ID · 리전(전역 서비스는 global)이 보인다

## 서비스별 목록과 상세 (각 타입: 목록 표시, 행 선택 시 상세, 콘솔 열기 동작)
- [ ] EC2: Instances / Security Groups / Volumes
- [ ] S3: Buckets → 목록과 상세 확인 (버킷 더블클릭/Enter는 `S3: 버킷` 탭으로 열려요)
- [ ] Lambda: Functions
- [ ] RDS: DB Instances / DB Clusters
- [ ] ECS: Clusters / Services / Tasks
- [ ] EKS: Clusters / Node Groups
- [ ] VPC: VPCs / Subnets
- [ ] IAM: Users / Roles / Policies
- [ ] DynamoDB: Tables
- [ ] CloudWatch Logs: Log Groups
- [ ] CloudFront: Distributions
- [ ] SQS: Queues
- [ ] SNS: Topics
- [ ] ECR: Repositories
- [ ] Route53: Hosted Zones
- [ ] Secrets Manager: Secrets (시크릿 값은 어디에도 표시되지 않는다)

## 조작
- [ ] ⌘F 필터 포커스, Esc로 필터 지우기
- [ ] ⌘R 새로고침 후 상태바 시간이 갱신된다
- [ ] 행 선택 후 ⌘C로 ID(S3는 s3:// URI) 복사
- [ ] ↑↓로 행 이동, Enter로 S3 버킷/폴더 열기
- [ ] 리소스 타입 우클릭으로 즐겨찾기 추가/제거
- [ ] ⚙에서 서비스를 끄면 사이드바에서 즉시 사라진다
- [ ] 원본 데이터 보기 모달이 열리고 닫힌다

## 오류
- [ ] `aws sso logout --profile <p>` 후 조회 → "SSO 세션이 만료됐어요" + 로그인 버튼 → 로그인 후 자동 재조회
- [ ] 권한 없는 타입은 "권한 없음 (액션)"만 표시하고 다른 타입은 정상 동작
- [ ] 네트워크 끊고 조회 → 네트워크 오류 + 다시 시도

## S3 탐색기 (테스트용 버킷에서만 확인)
- [ ] 리소스 탭에서 버킷 더블클릭/Enter → `S3: 버킷` 탭이 열리고, 같은 버킷은 기존 탭으로 이동, 프로필 변경 시 버킷 탭이 닫힌다
- [ ] 앱 시작 시 탭은 "리소스"만 있고, 버킷을 열면 `S3: 버킷` 탭이 생긴다. 리소스 탭으로 돌아와도 선택·스크롤이 유지된다
- [ ] 로컬 패널: 홈에서 시작, 폴더 진입/↑, 경로 직접 입력, 앱 재시작 시 마지막 경로 복원
- [ ] S3 패널: 버킷 목록 → 버킷(다른 리전 버킷 포함) → 폴더, 경로 클릭 이동, "더 보기"
- [ ] 로컬 → S3 드래그 업로드(파일, 폴더), Finder → S3 패널 드롭 업로드, [복사 →]
- [ ] S3 → 로컬 드래그 다운로드(파일, 폴더), [← 복사], 다운로드 진행률 표시
- [ ] 같은 이름이 있으면 덮어쓰기 확인(모두 덮어쓰기 / 충돌 건너뛰기 / 취소)
- [ ] 새 폴더, 파일 이름 변경, 폴더 이름 변경(하위 객체 이동), 이름 충돌 시 덮어쓰기 확인
- [ ] 삭제 확인 창의 객체 수가 맞고, 폴더 삭제 시 하위 객체까지 삭제된다
- [ ] 쓰기 권한 없는 버킷에서 업로드/삭제 시 "권한 없음 (s3:PutObject)" 등이 표시된다
- [ ] 전송 실패 항목 [재시도], [완료 항목 지우기]
- [ ] 표의 빈 공간을 클릭하면 선택이 해제되고, 이미 선택된 행을 천천히 다시 클릭해도 해제된다(더블클릭은 그대로 열기)
- [ ] 마우스 뒤로/앞으로 버튼이 포인터가 있는 패널의 탐색 기록을 이동하고, ⌘[ / ⌘]는 포커스된 패널에 적용된다
- [ ] Tab으로 패널 포커스 전환, ⌘D 비교, ⌘⌫ 삭제(S3 패널)

## 파일 비교
- [ ] 로컬↔S3, S3↔S3, 로컬↔로컬 비교 탭이 열리고, 같은 쌍을 다시 비교하면 기존 탭이 활성화된다
- [ ] 추가/삭제/변경 줄 색과 줄 안 강조, "… N줄 같음" 펼치기, ▲/▼ 및 F7/⇧F7 이동
- [ ] 같은 파일이면 "두 파일이 같아요"
- [ ] 이미지 등 바이너리·2MB 초과 파일은 크기/수정일/MD5 비교와 판정 문구
- [ ] 비교 탭의 [S3로 업로드 →]/[← 로컬로 내려받기] 후 비교가 다시 계산된다
- [ ] [외부 도구로 열기]: FileMerge, VS Code, 직접 입력 명령(설정 ⚙ → 비교 도구)
- [ ] ⌘C는 리소스 탭에서만 동작하고 탐색기/비교 탭에서는 리소스 ID를 복사하지 않는다

## 자동 업데이트
- [ ] 이전 버전을 설치한 상태에서 새 버전 릴리즈 후 앱 실행 → "새 버전 X이 나왔어요" 배너
- [ ] [나중에] → 배너 숨김, 설정 → 업데이트 확인 → 다시 표시
- [ ] 파일 전송 중 [지금 업데이트] → "파일 전송이 끝난 뒤에" 안내, 전송 후 업데이트 → 진행률 → 앱 재시작 후 새 버전
- [ ] 오프라인에서 시작해도 오류 없이 동작, 설정에서 직접 확인하면 오류 문구 표시

## VPC 구조도
- [ ] 리소스 → VPC → VPCs에서 VPC를 더블클릭(또는 Enter)하면 `🗺 <이름>` 탭이 열리고, 같은 VPC를 다시 열면 기존 탭이 활성화된다
- [ ] AZ 열 × 퍼블릭/프라이빗/격리 행으로 서브넷이 배치되고, 서브넷 안에 EC2/NAT/RDS/ELB/Lambda/VPCE 타일이 보인다
- [ ] IGW 등은 VPC 위 테두리, S3/DynamoDB 엔드포인트·TGW·피어링은 아래 "외부 연결" 띠에 보인다
- [ ] 여러 서브넷에 걸친 ELB 등에 마우스를 올리면 같은 리소스 타일이 함께 강조된다
- [ ] 서브넷 클릭 → 오른쪽에 라우팅 테이블·경로 목록, 기본 경로 대상(IGW/NAT/TGW)이 주황으로 강조된다. 빈 곳 클릭/Esc로 선택 해제
- [ ] 휠/트랙패드로 커서 기준 확대·축소(30%~300%), 빈 곳 드래그로 이동, [맞춤] [100%] [−] [+]
- [ ] 다른 탭에 있을 때 휠/Esc가 구조도에 영향을 주지 않는다
- [ ] [PNG로 저장] → 저장 대화상자, 저장 후 "저장했어요", 취소하면 아무 일 없음. 저장된 PNG는 전체 구조도가 ×2 해상도로 들어 있다
- [ ] [새로고침]과 ⌘R이 구조도를 다시 불러온다. 권한이 없는 항목은 상단에 노란 경고로 표시된다
- [ ] 프로필을 바꾸면 VPC 탭이 닫힌다

## IAM 작업 공간: 탭과 읽기 화면
- [ ] 리소스 → IAM을 펼치면 첫 항목에 `🔐 IAM 관리`가 보이고, 누르면 `🔐 IAM · <계정ID>` 탭이 열린다. 다시 누르면 기존 탭으로 이동하고, 프로필을 바꾸면 탭이 닫힌다
- [ ] 리소스 탭 IAM의 Users / Roles / Policies에서 행을 더블클릭(또는 Enter)하면 IAM 탭이 그 사용자·역할·정책 상세로 열린다. 이미 열려 있으면 같은 탭에서 이동한다
- [ ] 첫 조회는 계정 크기에 따라 몇 초 걸리고 그동안 "IAM 정보를 불러오는 중이에요"가 보인다. 권한이 부족하면 "권한 없음 (iam:…)", SSO가 만료됐으면 로그인 버튼이 보인다
- [ ] 왼쪽 메뉴: 점검(건수) · 사용자 · 그룹 · 역할 · 정책 · 누가 할 수 있나 · 변경 기록. IAM 탭은 점검 화면으로 열리고, 변경 기록은 변경을 한 번도 안 했다면 "변경 기록이 없어요"가 보인다
- [ ] 모든 화면 위에 "조직 SCP와 리소스 기반 정책은 반영하지 않아요" 안내가 보이고, 상단에 조회 시각과 [새로고침]이 있다. ⌘R(또는 ⟳)로 IAM 정보를 다시 읽는다
- [ ] 목록: 이름(경로), 상태 배지(MFA 없음·관리자급·서비스 연결 등), 마지막 사용, 정책 수(그룹은 구성원 수, 정책은 붙은 곳 수·범위·수정일). 머리글 클릭으로 정렬, ↑↓ 이동, Enter/더블클릭으로 상세, 툴바 필터(⌘F)로 이름·ARN 필터
- [ ] 사용자·역할·그룹 상세 머리글: 이름, ARN과 [복사], 배지, 만든 날, 마지막 사용, 태그. 하위 탭은 사용자 = 권한·정책·그룹·액세스 키·안 쓰는 권한, 역할 = 권한·정책·신뢰·안 쓰는 권한, 그룹 = 권한·정책·구성원
- [ ] 권한 탭: 서비스 × 목록·읽기·쓰기·권한 관리·태그 표에 허용/전체 수가 보이고 조건부(◐)·거부·경계(⊘) 수가 작게 붙는다(⊘는 거부와 권한 경계로 막힌 작업을 합친 수이고, 칸을 누르면 둘이 나뉘어 보인다). 위험 작업이 있는 서비스에 ⚠가 보이고, 서비스 필터가 동작한다. 권한 경계 등 설명은 표 위에, 카탈로그에 없는 작업은 표 아래에 보인다
- [ ] 관리자급 주체(AdministratorAccess 등)는 표 위에 "모든 서비스의 모든 작업이 허용돼요"가 보인다
- [ ] 칸을 누르면 오른쪽에 작업 목록이 열린다: 작업별 상태(허용·조건부·거부·경계로 차단), 위험 사유, 대상 리소스, 근거(정책, 상속한 그룹, Sid 또는 문장 번호, 조건 있음, Deny). 같은 칸을 다시 누르거나 ✕로 닫고, 근거 정책 이름을 누르면 그 정책 상세로 이동한다
- [ ] 정책 탭: 직접 연결 / 그룹에서 상속 / 인라인 / 권한 경계로 나뉘고, 정책 이름은 정책 상세로, 상속한 그룹 이름은 그룹 상세로 이동한다
- [ ] 그룹 탭(사용자)과 구성원 탭(그룹)의 이름을 누르면 해당 상세로 이동한다
- [ ] 액세스 키 탭(사용자): 키 ID·상태·만든 날·나이·마지막 사용·서비스/리전. 비밀 키는 어디에도 표시되지 않는다
- [ ] 신뢰 탭(역할): 서비스·계정·연동·누구나 항목과 "외부", "조건 있음", 경고(누구나 맡을 수 있음, ExternalId 조건 없음 등)
- [ ] 정책 상세: 문장 표(효과·서비스별 작업 수준과 개수·대상·조건, NotAction/NotResource 표시), JSON과 [복사], 버전(기본 표시), 붙어 있는 대상(누르면 해당 상세로 이동)
- [ ] 뒤로/앞으로: 상단 ‹ ›, ⌘[ / ⌘], 마우스 뒤로/앞으로 버튼. 정책 상세를 보고 돌아오면 보던 하위 탭과 열어 둔 칸이 그대로 있고, 다른 탭에 있을 때·글자를 입력하는 중·확인 창이 떠 있을 때는 반응하지 않는다

## IAM 작업 공간: 점검, 누가 할 수 있나, 안 쓰는 권한
- [ ] IAM 탭을 열면 점검 화면이 먼저 보인다. 카드 11개(루트 액세스 키 · 루트 MFA 없음 · MFA 없는 콘솔 사용자 · 오래된 액세스 키 · 안 쓰는 액세스 키 · 안 쓰는 사용자 · 안 쓰는 역할 · 관리자급 주체 · 권한 상승 위험 주체 · 외부에 열린 신뢰 · 붙은 곳 없는 정책)가 이 순서로 보이고, 건수와 위험/주의/참고 색이 붙는다. 문제가 없는 카드는 흐리게 "문제 없음"으로 보이고 눌리지 않는다
- [ ] 문제가 있는 첫 카드가 처음부터 선택돼 있고, 다른 카드를 누르면 아래 목록이 바뀐다. 목록은 대상 · 내용 · 조치로 나뉜다. 대상 이름을 누르면 사용자·역할·정책 상세로 이동하고(루트 계정은 글자만 보인다), 액세스 키 점검의 대상은 그 사용자의 액세스 키 탭으로 열린다. 상세를 보고 뒤로 가면 보던 카드가 그대로 선택돼 있다
- [ ] 항목마다 CLI 명령이 보이고 [CLI 복사]가 클립보드에 복사한다. 터미널에 붙여 넣어 확인한다(키 ID를 모르는 항목은 `<ACCESS_KEY_ID>`를 직접 채워야 한다). 명령이 없는 항목(루트 MFA 등)에는 복사 버튼이 없다
- [ ] 위쪽에 "기준 …" 시각이 보이고, 자격 증명 보고서를 못 읽었을 때 등의 경고는 노란 줄로 보인다. 문제가 하나도 없는 계정에서는 "발견된 문제가 없어요"가 보인다
- [ ] 오래된·안 쓰는 액세스 키 항목에서 앱이 그 키를 찾았으면 CLI 명령에 실제 키 ID가 들어가고 [키 비활성화] 빠른 조치가 보인다. 이 버튼은 바로 바꾸지 않고 "변경 미리보기" 창을 연다(아래 "직접 변경" 절 참고). 자격 증명 보고서를 못 받은 계정에서는 보고서가 필요한 점검 카드(루트 액세스 키 · 루트 MFA 없음 · MFA 없는 콘솔 사용자 · 오래된/안 쓰는 액세스 키 · 안 쓰는 사용자)가 "문제 없음" 대신 "확인할 수 없어요 (자격 증명 보고서 없음)"로 보인다
- [ ] 누가 할 수 있나: 작업 칸에 `s3:get`처럼 일부만 치면 자동 완성 목록이 뜬다(최대 50개, 앞부분이 맞는 작업이 먼저). ↑/↓로 옮기고 Enter로 고른 뒤 Enter를 한 번 더 누르면 검색한다. Esc로 목록을 닫고, 목록이 닫힌 채 ↓를 누르면 다시 열린다. 마우스로 고를 수도 있다
- [ ] 대상 ARN을 비우면 모든 리소스, 채우면 그 ARN에 적용되는 문장만 본다(예: `s3:GetObject` + `arn:aws:s3:::<테스트 버킷>/*`). 대상 ARN 칸에서 Enter를 눌러도 검색한다. 같은 조건으로 [찾기]를 다시 누르면 다시 계산한다
- [ ] 결과 표: 주체(사용자·역할과 배지) · 결과(허용 · 조건부 · 경계로 차단 · 거부) · 근거(정책, 상속한 그룹, Sid 또는 문장 번호, 조건 있음, Deny, 권한 경계). 위쪽에 찾은 작업·대상 ARN·주체 수와 안내 문구가 보이고, 해당하는 주체가 없으면 "이 작업을 할 수 있는 사용자와 역할이 없어요"가 보인다
- [ ] 결과의 주체·정책·그룹 이름을 누르면 해당 상세로 이동한다. 뒤로 가면 작업·대상 ARN 입력과 같은 결과가 그대로 있다. 다른 화면을 거쳐 메뉴로 다시 들어오면 빈 입력창으로 시작한다
- [ ] [AWS로 확인]: "AWS 정책 시뮬레이터로 확인하는 중이에요…"가 보이고, 끝나면 "AWS 확인" 열에 허용 / 허용 안 됨 / 명시적 거부가 주체마다 붙는다. 앱이 계산한 결과와 다른 주체가 없는지 본다. 시뮬레이터가 비어 있다고 한 조건 키는 칸 아래에 보인다. iam:SimulatePrincipalPolicy 권한이 없으면 "권한 없음"이 보이고 결과 표는 그대로다
- [ ] 안 쓰는 권한 탭(사용자·역할): 처음에는 설명과 [불러오기]만 보인다. 누르면 "마지막 사용 시각을 모으는 중이에요" 문구가 보이고(10~30초), 끝나면 서비스별 마지막 사용 표가 보인다. 안 쓴 서비스가 "사용 안 함 (400일)"로 맨 위에, 그다음은 마지막 사용이 오래된 순이다
- [ ] 다른 하위 탭이나 정책 상세에 갔다 와도 불러온 결과가 그대로 있고, ⌘R이나 [새로고침]이 이 작업을 다시 시작하지 않는다. [다시 불러오기]를 누르면 이전 결과를 둔 채 새로 받는다. iam:GenerateServiceLastAccessedDetails 권한이 없으면 "권한 없음"이 보이고 [불러오기]를 다시 누를 수 있다
- [ ] 통째로 안 쓰는 정책 표: 정책 이름은 정책 상세로 이동하고, 그룹에서 상속한 정책은 [떼기]가 꺼진 채 "그룹 <이름>에서 떼야 해요"와 그룹 링크가 보인다. 통째로 안 쓰는 정책이 하나도 없으면 "통째로 안 쓰는 정책이 없어요"가 보인다
- [ ] 줄인 정책 초안: JSON이 들여쓰기돼 보이고 [복사]가 동작한다. 초안 아래에 "사용 기록이 없는 권한은 빠져 있어요", "저장해도 지금 붙어 있는 정책은 그대로예요" 안내와 초안 메모(조건을 버렸다는 등)가 보인다. [떼기]와 [인라인 정책으로 저장]은 변경 미리보기를 연다(서비스 연결·Identity Center 역할이면 꺼져 있고 이유가 보인다)

## IAM 작업 공간: 직접 변경 (테스트 계정에서만 확인한다)
준비: 운영과 분리된 테스트 계정/프로필에 테스트 사용자(액세스 키 2개), 테스트 그룹, 테스트용 고객 관리형 정책을 만들어 둔다. 아래 변경은 모두 실제 IAM에 쓰기 때문에 운영 계정에서는 하지 않는다. 쓰는 자격 증명에는 해당 쓰기 권한(iam:AttachUserPolicy, iam:DetachUserPolicy, iam:PutUserPolicy, iam:DeleteUserPolicy, iam:AddUserToGroup, iam:RemoveUserFromGroup, iam:UpdateAccessKey, iam:DeleteAccessKey, iam:CreatePolicyVersion 등)이 있어야 한다.

- [ ] 미리보기 창 공통: 변경 버튼은 바로 바꾸지 않고 "변경 미리보기" 창을 연다. 요약, 호출할 API(인자 포함), 영향받는 주체별 얻는 권한(초록 ＋)·잃는 권한(빨강 －)(서비스 · 수준 · 개수와 예시 작업), "되돌릴 수 있어요/없어요"가 보인다. 미리보기를 받는 동안 [적용]은 꺼져 있다. 처음 초점은 [취소]이고 Esc가 취소하며 Enter로는 적용되지 않는다. 창이 떠 있는 동안 ⌘[ / 마우스 뒤로·앞으로는 반응하지 않는다
- [ ] 정책 붙이기: 사용자의 정책 탭 [정책 붙이기] → 이름 일부로 검색(고객/AWS 관리형 구분, 배지, 설명, 최대 100개 안내), ↑↓ Enter로도 고를 수 있다. 이미 직접 붙은 정책은 "이미 붙어 있어요"로 선택되지 않는다. 고르면 미리보기가 열리고 [적용] 뒤에 "…붙였어요 · 반영까지 몇 초 걸릴 수 있어요" 안내가 보이며, 정책 목록이 바로 한 번, 3초 뒤 한 번 더 새로 읽힌다(안내는 ✕로 닫거나 10초 뒤 사라진다. 변경 기록을 저장하지 못했을 때처럼 함께 알릴 일이 붙은 안내는 ✕로 닫을 때까지 남고, 다음 적용의 안내가 덮지 않는다). 그룹·역할에도 같은 [정책 붙이기]가 있다
- [ ] 정책 떼기: 직접 붙은 관리형 정책 줄에만 [떼기]가 있다. 그룹에서 상속한 줄은 "그룹 <이름>에서 떼야 해요" 안내와 그룹 링크만 있고(인라인이면 "지워야 해요"), 권한 경계 줄에는 버튼이 없다. 떼기 미리보기에서 잃는 권한이 빨강으로 보인다
- [ ] 인라인 정책: [인라인 정책 추가] → 이름 + JSON 편집기(고정폭). Tab은 공백 2칸을 넣고 Esc 다음 Tab(또는 Shift+Tab)은 초점을 옮긴다. JSON이 틀리면 바로 빨간 안내가 나오고 [검사]·[미리보기]가 꺼진다. 이름 규칙(영문자·숫자·+ = , . @ _ -, 128자)과 같은 이름 거부("같은 이름의 인라인 정책이 이미 있어요")를 확인한다. [검사]는 AWS 정책 검사기 결과를 오류 · 보안 경고 · 경고 · 제안 순서로 보여주고, 권한이 없으면 "JSON 문법만 확인했어요"가 보인다. [미리보기] → [적용] 뒤에 편집기가 닫히고 목록에 나타난다. 미리보기에서 [취소]하면 편집기와 입력한 내용이 그대로다
- [ ] 인라인 [편집]은 현재 문서를 불러와 채우고, 바꾼 내용이 없으면 [미리보기]가 꺼져 있다. 인라인 [삭제]는 이름 입력 확인(아래)을 요구한다
- [ ] 이름 입력 확인: 인라인 정책 삭제, 액세스 키 삭제, 지금 쓰는 자격 증명(또는 그 자격 증명이 속한 그룹)의 권한을 줄이는 변경은 "확인하려면 <이름>를 입력하세요" 칸이 나온다(입력할 값은 대상의 이름이고, 액세스 키 삭제는 키 ID다). 정확히 같게 입력하기 전에는 [적용]이 꺼져 있다(대소문자·앞뒤 공백이 달라도 안 된다). 입력이 다르면 "입력한 이름이 달라요"가 보이고, 새 미리보기를 받으면 입력이 비워진다. [적용]은 빨간 위험 스타일이다
- [ ] 막힘: 서비스 연결 역할(AWSServiceRoleFor…)과 Identity Center 역할(AWSReservedSSO_…)은 정책 탭의 [정책 붙이기] [인라인 정책 추가] [떼기] [편집] [삭제]와 안 쓰는 권한 탭의 조치 버튼이 꺼져 있고 이유가 보인다. AWS 관리형 정책 상세에는 [편집]이 없다. 막힘(빨강) 경고가 있는 미리보기는 [적용]이 꺼져 있고 "막힘 경고가 있어서 적용할 수 없어요"가 보인다. 주의(노랑) 경고(CloudFormation 스택 태그, 영향받는 주체 5명 이상 등)는 적용할 수 있지만 [적용]이 위험 스타일이다
- [ ] 그룹: 사용자의 그룹 탭 [그룹에 추가](이미 속한 그룹은 선택 불가)와 각 줄 [빼기], 그룹의 구성원 탭 [사용자 추가](이미 구성원인 사용자는 선택 불가)와 각 줄 [빼기]. 미리보기에서 영향받는 주체와 권한 증감을 확인한다
- [ ] 액세스 키(사용자 → 액세스 키 탭): Active 키에는 [비활성화], Inactive 키에는 [활성화], 둘 다 [삭제]. 삭제는 "되돌릴 수 없어요"와 이름 입력 확인이 나온다. 점검 화면의 키 비활성화 빠른 조치도 같은 미리보기를 연다. 비밀 키는 어디에도 나오지 않는다
- [ ] 정책 상세 [편집]: 고객 관리형은 편집기가 현재 기본 버전 문서로 열리고, 바꾼 뒤 미리보기 → 적용하면 새 기본 버전이 만들어진다(버전이 5개면 가장 오래된 비기본 버전을 먼저 지운다는 주의 경고). 인라인 정책 상세의 [편집]은 그 정책을 가진 사용자·그룹·역할에 저장한다. 적용 후 버전 탭이 갱신된다
- [ ] 적용 실패(예: 쓰기 권한이 없는 프로필): 미리보기 창이 열린 채로 "적용하지 못했어요"와 오류가 버튼 위에 보이고, [적용]은 꺼지며 초점이 [미리보기 다시 받기]로 간다. 다시 받은 뒤에 적용할 수 있다. 실패한 시도도 변경 기록에 남는다

확인 경고와 거부는 실제 AWS에서만 끝까지 확인할 수 있다(자격 증명의 키 ID, Access Analyzer, IAM 반영 지연). 아래도 테스트 계정에서 확인한다.

- [ ] 관리자급·권한 상승: 테스트 사용자에게 AdministratorAccess를 붙이는 미리보기에 "관리자급 권한을 새로 얻는 주체: <사용자>" 확인이 나오고, 사용자 이름을 입력해야 [적용]이 켜진다. `iam:PassRole`을 `"Resource": "*"`로 여는 고객 관리형 정책을 붙이면 "권한 상승에 쓸 수 있는 권한을 새로 얻는 주체: <사용자>" 확인이 나온다
- [ ] 이 앱이 쓰는 키: 테스트 사용자의 액세스 키로 만든 프로필로 앱을 열고, 그 사용자의 액세스 키 탭에서 지금 쓰는 키를 [비활성화]하면 "적용하면 이 앱이 바로 AWS에 접근하지 못하고, 여기서는 되돌릴 수 없어요" 확인이 나오고 입력할 값은 그 키 ID다. "되돌릴 수 없어요"가 보인다. 같은 사용자의 다른 키를 [비활성화]하면 이 확인이 나오지 않는다. `role_arn` + `source_profile` 프로필에서는 원본 프로필의 키를 끄는 미리보기에도 이 확인이 나오지 않는다(알려진 한계)
- [ ] 조건부 Deny(MFA): MFA 없이 키로 접근하는 앱의 사용자가 속한 그룹에 AWS 문서의 "MFA가 없으면 거부" 정책(`BoolIfExists` `aws:MultiFactorAuthPresent` `false`)을 붙이는 미리보기에 "조건에 따라 이 앱의 자격 증명이 막힐 수 있어요 (예: MFA·IP 조건)"와 "이 변경을 되돌리는 데 필요한 권한(iam:DetachGroupPolicy)도 조건부가 돼서 이 자격 증명으로는 되돌리지 못할 수 있어요" 확인이 나오고, 그룹 이름을 입력해야 한다. "되돌릴 수 없어요"가 보인다. 확인한 뒤 [취소]한다
- [ ] 크기 한도: 사용자 인라인 정책에 공백을 뺀 글자가 2,048자를 넘는 문서를 넣으면 "사용자 인라인 정책은 모두 합쳐 공백을 뺀 2,048자까지 쓸 수 있어요…" 막힘이 나온다. 들여쓰기와 줄바꿈이 많아 전체 길이는 2,048자를 훨씬 넘지만 공백을 뺀 글자는 한도 안인 문서는 막히지 않고, 적용하면 AWS도 받아들인다. 관리형 정책 편집(6,144자)도 같은 방법으로 확인한다
- [ ] 미리보기 뒤에 바뀐 IAM: 미리보기를 연 채로 콘솔이나 CLI에서 같은 대상을 바꾼다(예: 붙이려던 정책을 먼저 붙이기, 편집하려는 고객 관리형 정책의 버전을 5개로 채우기). [적용]하면 "미리보기 뒤에 IAM이 바뀌었어요. 미리보기를 다시 받아 주세요."로 거부되고 IAM은 그대로다(변경 기록에도 남지 않는다). [미리보기 다시 받기] 뒤에는 바뀐 내용(이미 붙어 있다는 주의, 버전 삭제 호출 등)이 보이고, 그 미리보기는 적용할 수 있다
- [ ] 버전 삭제 전 정책 검사: 버전이 5개인 고객 관리형 정책을 편집한다. `access-analyzer:ValidatePolicy` 권한이 없는 프로필이면 "정책 검사를 할 수 없어 버전 삭제 뒤 저장이 실패할 수 있어요" 확인(정책 이름 입력)이 나온다. 권한이 있는 프로필에서 Access Analyzer가 오류(ERROR)를 내는 문서(예: 잘못된 리소스 ARN)로 고치면 "정책 문서에 오류가 있어 적용할 수 없어요: …" 막힘이 나오고 [적용]이 꺼진다. 두 경우 모두 지울 버전은 그대로 남아 있다
- [ ] 읽지 못한 정책: `iam:GetPolicy`를 거부한 프로필로 연다(상단에 "…정책을 불러오지 못했어요: 권한 없음 (iam:GetPolicy)" 경고). 앱이 쓰는 사용자를, 문서를 읽지 못한 관리형 정책이 붙은 그룹에서 빼는 미리보기는 영향 목록이 비어 있어도 "문서를 읽지 못한 정책이 있어 권한 변화를 다 계산하지 못했어요: <정책> (<그룹> 그룹)" 확인이 나오고 사용자 이름을 입력해야 한다. 아무 데도 안 붙은 AWS 관리형 정책을 붙이는 미리보기에도 같은 확인과 "<정책> 정책을 읽지 못했어요: 권한 없음 (iam:GetPolicy)" 주의가 나온다. 확인한 뒤 [취소]한다
- [ ] 액세스 키 빠른 조치: 오래되거나 안 쓰는 액세스 키가 있는 계정의 점검 화면에서, 그 항목의 CLI 명령에 든 `--access-key-id`가 사용자의 액세스 키 탭에 보이는 키 ID와 같다. [키 비활성화]를 누르면 "<사용자>의 액세스 키 <키 ID> 비활성화하기" 미리보기가 열리고, 적용하면 액세스 키 탭에서 그 키가 Inactive다. `iam:ListAccessKeys`를 거부한 프로필에서는 [키 비활성화] 없이 CLI 명령에 `<ACCESS_KEY_ID>`가 남고, 위쪽 경고에 "액세스 키 목록을 읽지 못해 … 권한 없음 (iam:ListAccessKeys)"가 보인다
- [ ] 변경 기록(🕘): 시각 · 프로필/계정 · 내용 · 결과(성공/실패, 실패 사유) · 되돌림 표시가 최신순으로 보이고, 앱을 재시작해도 남아 있다(앱 데이터 폴더의 iam-changes.jsonl). 성공한 변경에는 [되돌리기]가 있고, 누르면 "되돌리기 미리보기"가 열리며 [적용]하면 원래 항목에 "되돌림", 새 항목에 "되돌리기 기록"이 붙는다. 키 삭제처럼 되돌릴 수 없는 변경은 "되돌릴 수 없어요", 다른 계정에서 한 변경은 [되돌리기]가 꺼진 채 이유가 보인다
- [ ] 되돌리기 결과 확인: 붙이기 ↔ 떼기, 그룹 추가 ↔ 빼기, 키 상태 반대로, 인라인 저장은 이전 문서로 복원(원래 없던 정책이면 삭제), 관리형 편집은 이전 기본 버전 문서로 다시 편집된다
- [ ] 프로필을 바꾸면 IAM 탭과 함께 열려 있던 미리보기도 닫혀서, 다른 계정에 낡은 미리보기가 적용되지 않는다
